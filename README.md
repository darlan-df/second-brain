## Modelo de trabalho

**Estudar → sintetizar → relacionar → validar conhecimento → criar Skill → testar → revisar.**

O conhecimento explica *o que é, por que importa, como funciona e com quais fontes*. Uma Skill define *quando agir, quais entradas pedir, quais passos seguir, quais verificações executar e que saída produzir*.

### Convenções

- **Um arquivo por conhecimento**, quando desenvolvido; os índices descrevem os arquivos futuros.
- **Identificador estável do tema:** `NEG-01`, `ARQ-01`, `GPO-01`, `GPR-01`, `CEX-01`, `DAD-01`, `PES-01`, `IA-01`.
- **Fontes e edições:** registrar autor, título, versão/edição, data de consulta e link/identificador, quando existirem.
- **Separar** referencial bibliográfico, interpretação, hipótese e decisão local de aplicação.
- **Estados sugeridos de conhecimento:** planejado → em estudo → em revisão → validado → desatualizado.
- **Estados sugeridos de Skill:** rascunho → em teste → validada → revisão necessária.
- **Sem conteúdo fictício apresentado como norma:** usar exemplos fictícios apenas quando explicitamente identificados.
- **GitHub:** utilizar commits e pull requests para revisar alterações. Renomeações exigem conferir links cruzados e dependências das Skills.
